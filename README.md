# Telegram Chat через GREEN-API

Небольшой чат на React для отправки и получения **текстовых** сообщений через [GREEN-API для Telegram](https://green-api.com/telegram/docs/). Каждый пользователь вводит данные **своего** инстанса. Данные остаются в памяти API-сервера и не сохраняются в файлы. Браузер держит только случайный токен сессии в текущей вкладке (`sessionStorage`). Сессия живёт не более 8 часов; после перезапуска API-сервера подключение и история сбрасываются.

**Опубликованная версия:** [telegram-green-api-chat-six.vercel.app](https://telegram-green-api-chat-six.vercel.app/). Исходный код: [github.com/Tsirkova/telegram-green-api-chat](https://github.com/Tsirkova/telegram-green-api-chat). Сайт размещён на Vercel, API — на отдельном сервере. Укажите данные собственного Telegram-инстанса GREEN-API при входе.

## Подготовка

1. Создайте и авторизуйте **Telegram-инстанс** в кабинете GREEN-API. Нужны `apiUrl`, `idInstance` и `apiTokenInstance` из параметров доступа. [Инструкция GREEN-API](https://green-api.com/telegram/docs/before-start/).
2. В настройках инстанса включите входящие уведомления (`incomingWebhook: yes`) и оставьте `webhookUrl` пустым для [получения через HTTP API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/). Не запускайте одновременно другого потребителя той же очереди уведомлений.
3. Убедитесь, что аккаунт получателя доступен по номеру телефона: Telegram может скрывать его настройками приватности. Сервис GREEN-API для Telegram помечен как beta.

## Запуск

Требуется Node.js 20 или новее. В папке проекта выполните:

```powershell
npm install
npm run server
```

Во втором терминале:

```powershell
npm run dev
```

Откройте `http://127.0.0.1:5173`, введите данные инстанса, затем номер получателя в международном формате. Сервер слушает только `127.0.0.1:3001`, Vite проксирует `/api` на него.

## Публикация: Vercel + свой сервер

**API на своём сервере.** Для Linux-сервера подготовлены `compose.api.yml` и `Caddyfile.api`. Скопируйте `.env.api.example` в `.env.api`; задайте `FRONTEND_ORIGINS` как точный HTTPS-адрес сайта Vercel и `API_HOST` как DNS-имя API. На сервере в папке проекта выполните `docker compose -f compose.api.yml up -d --build`. API публикуется только на `127.0.0.1:3001`, а Caddy обслуживает HTTPS для `API_HOST` через порты 80/443. Если собственного домена нет, можно использовать бесплатное DNS-имя с IP в `sslip.io`; при смене IP адрес нужно обновить. Перед запуском проверьте занятость портов 80/443 и настройки VPN. Не открывайте порт 3001 наружу.

**Сайт на Vercel.** Создайте GitHub-репозиторий с этой папкой и импортируйте его в Vercel. Для проекта задайте переменную сборки `VITE_API_BASE_URL=https://api.example.com` (укажите ваш `API_HOST`, без `/api` на конце). Это публичный адрес API, **не секрет**. Vercel собирает Vite-приложение из `dist`; GREEN-API токены в Vercel не задаются. После первого развёртывания внесите точный адрес сайта Vercel в `.env.api` на сервере и перезапустите API-контейнер. Если адрес сайта изменится, обновите `FRONTEND_ORIGINS`. При изменении `VITE_API_BASE_URL` запустите новое развёртывание сайта.

Для этого проекта Vercel связан с локальной папкой через CLI. Автоматическое развёртывание из GitHub требует отдельного подключения GitHub к аккаунту Vercel. Пока оно не подключено, после изменения кода запустите `npx vercel deploy --prod` из папки проекта. Переменная `VITE_API_BASE_URL` уже задана в проекте Vercel для production и preview.

Браузер делает запросы напрямую к вашему API по HTTPS. Сервер разрешает запросы только с адресов из `FRONTEND_ORIGINS` (несколько адресов перечисляются через запятую). Для предварительных Vercel-превью добавляйте их точные адреса отдельно. Каждый браузер получает собственный токен сессии; сервер хранит учётные данные каждого пользователя отдельно.

## Проверка

```powershell
npm test
npm run build
```

Для сквозной проверки нужны два реальных Telegram-аккаунта: отправьте сообщение из веб-чата, ответьте из приложения Telegram и дождитесь ответа в интерфейсе (опрос раз в 5 секунд). Отправка через `SendMessage` возвращает ID поставленного в очередь сообщения, поэтому отображение в чате не означает гарантированную доставку адресату.

Приложение рассчитано на один активный личный чат на сессию. При открытии другого чата текущая история в памяти сбрасывается. Уведомления других чатов и нетекстовые события из очереди подтверждаются, но не отображаются. Один инстанс GREEN-API должен использоваться одним активным потребителем очереди: при одновременном входе с одинаковыми данными в разные сессии входящие сообщения могут распределиться между ними. Для публичного сервера обеспечьте HTTPS и ограничение доступа к панели управления VPN.
